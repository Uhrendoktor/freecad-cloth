# Pattern data model

The core pattern model is independent of FreeCAD GUI classes. Pattern pieces and seams use explicit stable IDs; recomputation may change coordinates but must not generate new IDs while topology is unchanged.

## Schema

`PatternDocument` uses `schema_version` (currently `1`) and contains a document ID, display name, piece records, seam records, and extensible metadata. JSON serialization is canonical (`sort_keys`, compact separators) so equivalent documents produce identical bytes.

A piece has a stable `id`, name, outline, seam allowance, grainline angle, and metadata. A seam has its own stable ID, two piece IDs, edge references, normalized ranges, and an orientation flag. This leaves room for richer edge-ID references as the geometry model evolves.

## Persistence contract

Save/load must preserve IDs and schema version. Unknown schema versions are rejected rather than silently interpreted. `PatternSchema.migrate()` is the explicit migration entry point for future versions.

FreeCAD document objects should adapt to this model rather than becoming required by it. Simulation adapters consume the same model and must not import GUI classes.

## Limitations

Schema version 1 intentionally stores JSON-like records rather than serializing FreeCAD `Shape` objects. Geometry remains generated by the parametric geometry layer. Future schema migrations must be explicit and tested.
