# Tool inventory

This inventory lists every checked-in tool, CI program, AST policy/rule fixture, and tool-owned data file under `tools/` (package marker files are excluded). Entries describe the role of the file and why it is worth keeping. When a tool is added, removed, renamed, or superseded, update this list in the same change and review whether an existing entry should be pruned.

- `tools/benchmark_workbenches.py` — **Goal:** Measure workbenches in a repeatable run. **Why useful:** Makes performance regressions measurable and keeps optimization decisions evidence-based.
- `tools/benchmarks/benchmark_geometry_libraries.py` — **Goal:** Measure geometry libraries in a repeatable run. **Why useful:** Makes performance regressions measurable and keeps optimization decisions evidence-based.
- `tools/check_dead_code.py` — **Goal:** Run Vulture only on high-confidence dead code inside the selected core packages. **Why useful:** Identifies removable production code while avoiding noisy false positives from dynamic FreeCAD plugin and GUI entry points.
- `tools/check_documentation_contract.py` — **Goal:** Verify parameter, return/yield, and raised-exception documentation across tracked Python sources and stubs, without inline lint suppressions. **Why useful:** Makes public and internal APIs understandable and catches documentation drift in CI.
- `tools/check_markdown_contract.py` — **Goal:** Validate local Markdown links and embedded image references across the repository documentation. **Why useful:** Catches dead pages and missing media before users encounter broken guides.
- `tools/ci/build_visual_gifs.py` — **Goal:** Build visual gifs from validated source artifacts. **Why useful:** Produces repeatable derived artifacts without hand-editing tracked inputs.
- `tools/ci/capture_pypbd_provenance.py` — **Goal:** Capture pypbd provenance from the active runtime. **Why useful:** Records reproducible provenance for native solver and environment-dependent results.
- `tools/ci/check_artifact_budget.py` — **Goal:** Calculate the accumulated size of artifacts uploaded by the current GitHub Actions run and compare it with the configured budget. **Why useful:** Prevents evidence publishing from silently exceeding storage limits or dropping artifacts to fit a budget.
- `tools/ci/check_changed_python_types.py` — **Goal:** Compare Ruff annotation diagnostics per changed Python file and rule against the merge base. **Why useful:** Prevents modified code from increasing typing debt while allowing unrelated historical debt to be retired incrementally.
- `tools/ci/check_explicit_any_annotations.py` — **Goal:** Reject explicit `Any` uses in aliases, attributes, quoted forward references, and legacy type comments. **Why useful:** Finds type-checking escape hatches that ordinary function-annotation rules can miss.
- `tools/ci/check_no_monkeypatch.py` — **Goal:** Detect test-time monkeypatching and global `sys.modules` replacement through AST inspection. **Why useful:** Keeps tests exercising real module behavior instead of passing because production code was replaced with test-only implementations.
- `tools/ci/check_no_source_rewriting.py` — **Goal:** Reject runtime rewriting of checked-in Python source and generated execution of source text. **Why useful:** Keeps execution paths inspectable and prevents validation results from depending on hidden code mutation.
- `tools/ci/check_pydantic_models.py` — **Goal:** Enforce Pydantic validation on production data-carrier dataclasses unless a concrete, tested serialization incompatibility is documented. **Why useful:** Ensures domain values are validated at their boundaries rather than relying on informal constructor discipline.
- `tools/ci/check_visual_asset_contract.py` — **Goal:** Require every documented README/wiki visual asset to be declared and produced by a CI workflow. **Why useful:** Prevents stale, untracked, or hand-edited screenshots from being mistaken for current evidence.
- `tools/ci/check_visual_assets_and_budget.py` — **Goal:** Execute both the visual-asset contract and accumulated-artifact budget checks, reporting failure if either fails. **Why useful:** Keeps asset provenance and storage budgets as independent gates without skipping one when the other reports an error.
- `tools/ci/create_agent_observation_bundle.py` — **Goal:** Create agent observation bundle from selected workflow artifacts. **Why useful:** Provides a consistent, inspectable output for diagnosis and review.
- `tools/ci/freecad_timeout_config.py` — **Goal:** Centralize default, minimum, and maximum durations for managed FreeCAD runs. **Why useful:** Keeps each runner from inventing its own timeout values and makes process-lifetime decisions auditable.
- `tools/ci/maintenance_cleanup.py` — **Goal:** Prune expired maintenance artifacts according to the repository retention rules. **Why useful:** Controls accumulated storage and reduces stale workflow state.
- `tools/ci/publish_pr_simulation_evidence.py` — **Goal:** Publish pr simulation evidence using the configured workflow boundary. **Why useful:** Keeps generated evidence reproducible and separates artifact publication from untrusted execution.
- `tools/ci/publish_visual_evidence.py` — **Goal:** Publish visual evidence using the configured workflow boundary. **Why useful:** Keeps generated evidence reproducible and separates artifact publication from untrusted execution.
- `tools/ci/pytest_collection_contract.py` — **Goal:** Fail a requested validation group when any explicitly selected test module collects no pytest items. **Why useful:** Prevents misspelled, empty, or silently skipped test selections from producing a false green result.
- `tools/ci/python_validation.py` — **Goal:** Run the canonical Python/FreeCAD validation groups in the configured CI environment and preserve each subprocess result. **Why useful:** Gives local and CI validation a single entry point with consistent group selection and failure reporting.
- `tools/ci/run_freecad.py` — **Goal:** Run run freecad through the supported execution boundary. **Why useful:** Keeps runtime selection, timeouts, logs, and process behavior consistent across CI and local use.
- `tools/ci/runner_watchdog.py` — **Goal:** Monitor local-runner readiness and route the canonical workflow to its allowed fallback. **Why useful:** Prevents trusted validation from stalling while preserving runner-routing policy.
- `tools/ci/scene_understanding_report.py` — **Goal:** Combine saved drape logs, geometry metrics, and image artifacts into a scene-understanding report with explicit fit-coverage caveats. **Why useful:** Makes visual/geometry findings reviewable from workflow artifacts after FreeCAD exits, without treating a heuristic as solver or contact acceptance.
- `tools/ci/timeout_contract.py` — **Goal:** Validate timeout inputs and reject absent, malformed, or unbounded values at the execution boundary. **Why useful:** Prevents a broken timeout setting from allowing a native FreeCAD process to hang validation indefinitely.
- `tools/ci/validate_acceptance.py` — **Goal:** Validate the expected GUI evidence files produced by named FreeCAD acceptance cases. **Why useful:** Stops an acceptance case from passing when its required screenshot or visual artifact is absent.
- `tools/ci/validate_ci_structure.py` — **Goal:** Check workflow layout, runner-routing rules, triggers, job dependencies, and required runtime contracts against the repository policy. **Why useful:** Catches changes that could bypass a gate, select an unsupported runner, or leave a validation path unbounded.
- `tools/ci/validate_manifests.py` — **Goal:** Validate the canonical simulation and visual-evidence manifests, including their scenario lists, checkpoints, and expected evidence records. **Why useful:** Keeps acceptance claims tied to a complete, repeatable set of recorded cases rather than ad hoc artifacts.
- `tools/ci/validate_realtime_benchmark.py` — **Goal:** Validate realtime-preview metric artifacts against the declared frame-rate budget, warmup, sample-count, and schema requirements. **Why useful:** Rejects malformed or incomplete performance evidence before it is used to approve runtime responsiveness.
- `tools/ci/validate_workbench_benchmark.py` — **Goal:** Validate schema-versioned startup/initialization benchmark results for the supported Pattern, Sewing, and Simulation workbenches. **Why useful:** Prevents missing measurements, invalid repeats, or malformed records from being interpreted as a successful performance comparison.
- `tools/ci/visual_asset_sources.json` — **Goal:** Declare the pinned asset inputs consumed by the visual-evidence checks. **Why useful:** Makes provenance reviewable and prevents visual validation from silently changing sources.
- `tools/ci/visual_evidence.py` — **Goal:** Compare public README/wiki image references against the declared visual-evidence inventory and validate their provenance. **Why useful:** Makes published images reproducible and flags a documented asset when its tracked source or expected generation path changes.
- `tools/crosshair_contracts.py` — **Goal:** Expose pure production functions for symbolic contract checking. **Why useful:** Finds edge cases beyond example-based tests while keeping symbolic execution bounded.
- `tools/generate_test_inventory.py` — **Goal:** Regenerate individual test-case entries from Python AST declarations and test docstrings. **Why useful:** Keeps case-level documentation synchronized with the suite and exposes stale, unlisted, or duplicate tests during review.
- `tools/merge_workbench_benchmark.py` — **Goal:** Merge workbench benchmark into one canonical result. **Why useful:** Prevents parallel workflow outputs from diverging or being interpreted inconsistently.
- `tools/plot_workbench_benchmark.py` — **Goal:** Plot workbench benchmark from saved benchmark data. **Why useful:** Makes performance trends reviewable without rerunning the workload or editing results manually.
