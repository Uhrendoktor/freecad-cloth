FreeCAD Cloth is a FreeCAD-native garment workflow. This README is the human-facing entry point; the detailed wiki-style documentation lives in <a href="docs/wiki/">docs/wiki/</a>.

The documentation follows one rule: <strong>a user-visible feature should be understandable from the page and visually inspectable from generated evidence.</strong> Technical contracts, tests and implementation files are linked beside the visual evidence so a human can audit the claim without reconstructing project history.

## How to read this documentation

Every feature page follows the same audit shape:

<strong>Purpose → What the user sees → How it behaves → Persistent state → Visual evidence → Human audit checklist → Automated evidence → Source files → Known boundaries</strong>

This separates three different questions:

1. Does the feature exist?
2. Does it behave as described?
3. Does the current visual evidence actually show it?

A green unit test is not a substitute for visual evidence, and a nice screenshot is not a substitute for a persistence or regression test.

## Visual evidence provenance

Public README and wiki images are generated artifacts. The canonical GitHub Actions workflow <a href=".github/workflows/canonical-execution.yml">canonical-execution.yml</a> generates and publishes the evidence set to the <code>docs/screenshots</code> branch.

Every merge to `main` runs the visual evidence publisher from that merge commit, and the publisher fails closed when the documented image inventory or provenance is stale.

The generated visual path is:

<pre>current main code
        ↓
canonical FreeCAD/Xvfb execution
        ↓
rendered evidence
        ↓
docs/screenshots
        ↓
README and wiki</pre>

Do not hand-edit a generated screenshot and treat it as product evidence. When the UI or geometry changes, the visual evidence must be regenerated by the canonical path.

## Project contracts

The saved FreeCAD document is the persistence authority.

| Concern | Authority |
| --- | --- |
| Editable 2D dimensions and constraints | Native FreeCAD Sketcher |
| Garment semantics | Cloth PatternPiece / sewing objects |
| Fitting scene | Persisted fitting and arrangement state |
| Mannequin pose | Persisted SkeletonPose / pose data |
| Collision target | <code>DrapeTarget</code> |
| Physics | Derived PositionBasedDynamics runtime state |
| Diagnostics | Derived inspection of valid simulation state |

The architecture page explains the dependency direction and reasons behind these boundaries: [Data model & architecture](docs/wiki/07-data-model.md).

## Scope

FreeCAD Cloth is deliberately not presented as complete commercial garment-CAD parity. The wiki distinguishes implemented workflows from named roadmap areas such as advanced grading/nesting, production construction libraries, richer avatar providers and measurement-grade fit analysis.
